# 스캔톡 v2 기획안 — 라운드별 실행 계획

> 기존 [06-business-model.md](06-business-model.md)(유료 카톡 분석)를 확장하는 새 방향 기획안입니다.
> 원칙: **한 라운드 = 하나의 검증 질문**. 통과 기준을 넘지 못하면 다음 라운드로 넘어가지 않고 수정합니다.

---

## 1. 한 줄 정의

**"재미로 해본 무료 검사가 나의 AI봇이 되고, 그 AI봇이 나 대신 소개팅을 뛰는 서비스"**

## 2. 전체 그림

```
무료 검사 ("내가 결혼할 확률은?")     ← 라운드 1
   ↓ 가입
나의 AI봇 생성 + 상대 봇과 대화        ← 라운드 2
   ↓ 자동사냥
나의 AI 탭에서 호감도 %만 확인         ← 라운드 3
   ↓ 임계치 도달
"실제 사람과 대화하시겠습니까?" → 결제  ← 라운드 4
```

핵심 재미 요소:
- 내 봇이 밖에서 무슨 대화를 하는지 **나는 절대 볼 수 없다** (궁금증이 재미)
- 매칭 전까지 완전 익명
- 한쪽만 수락하면 상대는 모른다 → **거절당하는 경험이 없다**
- **내 봇은 나와 대화할수록 나를 닮아간다** — 싱크로율 %를 키우는 육성 재미 (아래 4-1 참고)

### 4-1. 싱크로율 — 봇 육성 시스템

봇이 봇 주인과의 대화·피드백을 학습해 점점 주인을 닮아가고, 그 정도를 **싱크로율 %**로 보여준다.
다마고치처럼 "내 봇을 키우는" 재미가 매일 접속할 이유가 된다.

| 요소 | 내용 |
|------|------|
| 싱크로율 정의 | 내 봇이 나를 얼마나 닮았는가 (호감도 %와는 별개 지표 — 호감도는 상대와의 궁합) |
| 초기값 | 검사 완료 시 30% 수준에서 시작 (검사 4축만 반영된 상태) |
| 올리는 방법 | ① 내 봇과 직접 대화 ② 데일리 질문 카드 답변 ("오늘 기분은?", "이상형의 첫인상은?") ③ 봇의 발언에 좋아요/별로예요 피드백 |
| 보상 구조 | 싱크로율이 높을수록 → 자동사냥 대화 품질↑ → 호감도가 더 잘 오름 → 매칭 정확도↑ (육성이 실익으로 연결) |
| 연출 | 싱크로율 상승 애니메이션, 단계 명칭 (30% 어색한 사이 → 60% 닮은꼴 → 90% 또 다른 나) |
| 구현 방식 (현실) | 모델 파인튜닝이 아니라 **대화 메모리·성향 프로필 축적 + 프롬프트 반영**으로 구현. 비용은 대화당 API 호출 수준으로 통제 가능. "딥러닝 학습"은 마케팅 문구로만 사용 |

## 3. 화면 구조 (탭 2개)

| 탭 | 보여주는 것 | 안 보여주는 것 |
|----|------------|---------------|
| **챗** | 내가 직접 하는 대화 (상대 AI봇 🤖 / 매칭된 사람 💬) | — |
| **나의 AI** | **싱크로율 %** (내 봇이 나를 닮은 정도) + 상대 닉네임 + 호감도 % + 추이 ↑↓ | 대화 내용, 산출 근거 |

## 라운드 1 — 바이럴 검사로 리드 모으기 (2~3주)

**질문: 사람들이 검사를 하고, 공유하고, 가입까지 하는가?**

진행 순서를 4단계로 고정합니다:

```
1-A. POC 개발  →  1-B. 바이럴 콘텐츠 개발  →  1-C. 유입 KPI 측정  →  1-D. 인입 KPI 측정
```

### 1-A. POC 개발 (~1주)

콘텐츠를 붓기 전에, **검사 → 결과 → 공유 → 가입** 흐름이 도는 최소 뼈대를 먼저 만듭니다.

| 항목 | 내용 |
|------|------|
| 검사 플로우 | 문항 → 결과 미리보기 → 간편 가입 → 결과 전체 공개 (기존 성향 테스트 코드 재활용) |
| 측정 장치 | 처음부터 심는다: UTM 파라미터 처리 + 단계별 이벤트 기록 (방문/시작/완료/가입/공유 클릭) |
| 측정 도구 | 아래 "분석 스택 & 관리자 인사이트" 섹션의 4종 도구 + Supabase 이벤트 테이블 |
| 관리자 인사이트 v1 | 기존 /admin에 인사이트 탭 추가 — 유입·인입 KPI를 한 화면에서 확인 |
| POC 통과 기준 | 지인 10~20명 테스트에서 흐름 이탈 없이 완주, 이벤트가 정확히 쌓이는지 확인 |

> 측정 장치가 없는 POC는 의미가 없습니다. **KPI를 셀 수 있는 상태**가 POC의 완성 조건입니다.

### 1-B. 바이럴 콘텐츠 개발 (~1주, POC와 병행 가능)

| 항목 | 내용 |
|------|------|
| 주제 | "내가 결혼할 확률은?" (1개로 시작, 추가 콘텐츠는 검증 후) |
| 문항 | 24문항(약 5분) — 6개 파트 구성, 뒤에서 AI봇 성향 데이터로 재활용 가능하게 설계 |
| 결과 | 확률 % + 유형 이름 (밈이 될 한 줄 문구) |
| 결과 카드 | 인스타 스토리/카톡 공유용 이미지 카드 |
| CTA 1개 | "나와 어울리는 사람과 채팅하기" (라운드 2 예고, 사전신청 접수) |

### 1-C. 유입 KPI — "얼마나 들어오는가"

배포 채널별로 UTM을 달리해 **어디서 얼마나 오는지**를 셉니다.

| 지표 | 정의 | 초기 목표 (첫 2주) |
|------|------|-------------------|
| 방문자 수 | 검사 랜딩 도달 UV | 1,000명 (수동 시딩 기준) |
| 채널별 유입 | 인스타 릴스 / 커뮤니티(에타·블라인드) / 지인 공유 각각의 UV | 가장 효율 좋은 채널 1곳 식별 |
| 공유율 | 검사 완료자 중 공유 버튼 클릭 | 20% 이상 |
| 바이럴 계수 | 공유 1건당 신규 방문자 수 | 측정 후 기준 설정 (0.5 이상이면 합격적) |

### 1-D. 인입 KPI — "들어온 사람이 얼마나 남는가"

유입된 방문자가 퍼널을 따라 얼마나 깊이 들어오는지를 셉니다.

| 퍼널 단계 | 지표 | 통과 기준 |
|-----------|------|----------|
| 방문 → 검사 시작 | 시작률 | 60% 이상 |
| 검사 시작 → 완료 | 완료율 | 70% 이상 |
| 완료 → 가입 | 가입 전환율 | 30% 이상 |
| 가입 → 채팅 사전신청 | 사전신청률 | 30% 이상 |

**라운드 1 종료 판정**: 유입 KPI에서 유효 채널 1곳 + 인입 KPI 4단계 모두 통과 → 라운드 2 착수.
하나라도 크게 미달하면 라운드 2로 넘어가지 않고 해당 단계(콘텐츠 카피, 가입 UX 등)를 수정 후 재측정합니다.

### 만들지 않는 것
- AI봇, 채팅, 호감도 — 전부 라운드 2 이후
- 검사 콘텐츠 여러 개 — **1개로 검증 먼저**
- 광고 집행 — 수동 시딩으로 오가닉 반응 먼저 확인

### 현실 체크
- 개발량보다 **문항·결과 카피의 질**이 성패를 가름. 시간 배분을 기획 쪽에 둘 것.
- 유입 절대량이 적으면 인입 KPI가 통계적으로 무의미 → 최소 방문자 1,000명을 모은 뒤 판정.

## 라운드 2 — 나의 AI봇 + 봇과 대화 (3~4주)

**질문: 사람들이 남의 AI봇과의 대화를 재미있어 하는가?**

### 만드는 것

| 화면/기능 | 내용 |
|-----------|------|
| 봇 생성 | 검사 응답 → 봇 성향 프로필 자동 생성 (말투, 관심사, 연애 성향) |
| 챗 탭 | "어울리는 사람과 채팅하기" → 궁합 높은 **상대 유저의 봇**과 대화방 오픈 |
| 봇 대화 | 상대 봇이 그 사람의 검사 데이터 기반으로 응답 (익명, 닉네임만) |
| 호감도 v1 | 유저↔봇 대화 기반 단순 산출 (응답 길이, 왕복 횟수, 지속 일수) |
| 싱크로율 v1 | 내 봇과의 대화가 봇 프로필에 축적 → 싱크로율 % 상승. 검사 완료 시 30%에서 시작 |
| 안전장치 | 봇은 실명·연락처·위치를 묻지도 답하지도 않음 (프롬프트 가드레일) |

### 만들지 않는 것
- 봇↔봇 자동 대화 (자동사냥) — 비용이 곱으로 늘어나므로 라운드 3에서
- 나의 AI 탭 — 아직 보여줄 데이터가 부족
- 매칭/결제

### 통과 기준

| 지표 | 기준 |
|------|------|
| 가입 → 첫 봇 대화 시작 | 50% 이상 |
| 봇 대화 10턴 이상 지속 | 40% 이상 |
| 다음날 재방문 | 25% 이상 |

### 현실 체크
- **콜드 스타트**: 초기 유저가 적으면 대화할 봇이 없음 → 라운드 1의 사전신청자를 모아 **같은 날 오픈**하는 방식으로 초기 밀도 확보.
- 봇 응답 비용: 유저↔봇은 유저가 보낼 때만 호출되므로 통제 가능. 저비용 모델 + 턴당 응답 길이 제한.

## 라운드 3 — 매칭 파이프라인 + 자동사냥(보조) (3~4주)

**질문: 사람↔봇 호감도가 실제 매칭 수락으로 이어지는가?**

> 핵심 구조 정정 (2026-07-29): 메인 엔진은 **사람 ↔ 상대방의 봇** 대화다.
> 사람 A가 B의 봇과 대화해 호감도가 임계치에 도달하면 → **A와 B(봇 주인)의 매칭**을 제안한다.
> 봇↔봇 자동 대화(자동사냥)는 밀도를 높이는 **보조 기능**으로, 매칭 파이프라인 다음에 붙인다.

### 만드는 것

| 화면/기능 | 내용 |
|-----------|------|
| 봇↔봇 자동 대화 | 하루 1~2회 배치로 궁합 상위 상대와 자동 대화 (동시 상대 3명 제한) |
| 나의 AI 탭 | 싱크로율 % + 상대 목록 + 호감도 % + 추이 표시. **대화 내용은 절대 비공개** |
| 호감도 v2 | 성향 궁합(고정) + 대화 반응 + 지속성 합산 |
| 싱크로율 육성 루프 | 데일리 질문 카드 + 봇 발언 피드백(👍/👎) + 상승 연출·단계 명칭. **싱크로율↑ → 자동사냥 품질↑** 연결 |
| 알림 | "호감도가 올랐어요" / "봇이 물어볼 게 있대요" (내용은 알려주지 않음 → 궁금해서 접속) |

### 만들지 않는 것
- 매칭 전환/결제 — 라운드 4
- 봇 대화 내용 열람 기능 — **영구적으로 만들지 않음** (서비스 정체성)

### 통과 기준

| 지표 | 기준 |
|------|------|
| 나의 AI 탭 주 3회 이상 방문 | 30% 이상 |
| 호감도 임계치(75%) 도달 쌍 발생 | 주당 N쌍 (오픈 후 측정하여 설정) |

### 현실 체크
- **이 라운드가 비용의 고비.** 봇↔봇 대화는 유저가 없어도 API가 돈다. 배치 주기·상대 수·턴 수를 반드시 상한으로 묶고, 유저당 일일 비용 상한을 정할 것.
- 이 라운드 시작 전 결정: 시드 봇(운영자 봇) 허용 여부. 허용한다면 시드 봇과는 매칭 전환이 없어야 함.

## 라운드 4 — 진짜 매칭 + 첫 결제 (2~3주)

**질문: 매칭이 열리는 순간, 돈을 내는가?**

### 만드는 것

| 화면/기능 | 내용 |
|-----------|------|
| 매칭 제안 | 임계치 도달 시 양쪽에 "실제 사람과 대화하시겠습니까?" |
| 양측 수락 | 둘 다 수락해야 오픈. 한쪽만 수락 시 상대에게 알리지 않음 |
| 매칭 오픈권 | 첫 매칭은 무료, 두 번째부터 건당 4,900~9,900원 (기존처럼 수동 결제 확인으로 시작) |
| 사람 채팅방 | 기존 봇 대화방이 사람 대화방으로 전환되는 연출 |
| 안전 | 신고/차단, 성인 인증 (이 라운드 전 필수 도입) |
| 크로스셀 | 매칭 대화 시작 후 "이 대화 잘 되고 있을까요? 카톡 분석 받기" 노출 |

### 통과 기준

| 지표 | 기준 |
|------|------|
| 임계치 도달 쌍 중 양측 수락 | 40% 이상 |
| 매칭 오픈 결제 전환 (2번째부터) | 15% 이상 |
| 매칭 유저의 카톡 분석 구매 | 측정 후 목표 설정 |

### 현실 체크
- 결제는 기존 MVP와 동일하게 **수동 확인으로 시작** — 결제 API는 팔리는 게 확인된 뒤.
- 성인 인증은 법적으로 이 라운드 전에 필수. 인증 수단(PASS 등) 비용·개발량을 라운드 3 기간에 미리 조사.

## 분석 스택 & 관리자 인사이트 페이지

### 원칙

- **도구마다 역할 1개.** 역할이 겹치는 도구는 도입하지 않는다 (관리 비용도 비용이다).
- **판단의 기준 데이터는 자체 이벤트 테이블(Supabase).** 외부 도구는 보조·심층 분석용.
- 모든 도구는 무료 티어로 시작한다.

### 도구 구성

| 도구 | 역할 | 왜 이 도구인가 | 비용 |
|------|------|---------------|------|
| Supabase 이벤트 테이블 | **기준 데이터** — 퍼널 이벤트의 원본 저장 (방문/시작/완료/가입/사전신청/공유) | 자체 보유 데이터라 관리자 페이지에서 바로 조회 가능, 외부 도구 오차와 무관 | 기존 스택 |
| Vercel Analytics | 트래픽 총량, 페이지별 방문, Core Web Vitals | 배포 환경에 내장, 설정 제로 | 무료 티어 |
| GA4 | **채널 분석** — UTM 기반 유입 채널별 성과, 검색 유입 | 채널 어트리뷰션의 표준, 광고 집행 시 그대로 연결 | 무료 |
| PostHog | **행동 분석** — 퍼널 시각화, 리텐션, 세션 리코딩(어디서 이탈하는지 화면으로 확인) | 퍼널·리텐션·리코딩을 한 도구로 해결, 무료 티어 넉넉 | 무료 티어 |

> 히트맵 전용 도구(Clarity 등)는 PostHog 세션 리코딩과 역할이 겹치므로 도입하지 않는다.

### 관리자 인사이트 페이지 (기존 /admin에 "인사이트" 탭 추가)

외부 도구를 매번 열지 않고, **의사결정에 필요한 숫자만 한 화면에서** 보는 페이지. 데이터 소스는 Supabase 이벤트 테이블.

**v1 — 라운드 1과 함께 출시**

| 영역 | 보여주는 것 |
|------|------------|
| KPI 카드 | 오늘/7일/전체: 방문자, 검사 완료, 가입, 사전신청 |
| 퍼널 차트 | 방문 → 시작 → 완료 → 가입 → 사전신청 단계별 전환율 |
| 목표 대비 | 각 KPI에 라운드 1 통과 기준 표시 (예: 완료율 72% / 목표 70% ✅) |
| 채널별 표 | UTM 소스별 방문·가입 수 (유효 채널 식별용) |
| 기간 필터 | 오늘 / 7일 / 30일 / 전체 |

**v2 — 라운드 3과 함께 확장**

| 영역 | 보여주는 것 |
|------|------------|
| 봇 활동 | 일일 봇 대화 수, 유저당 평균 대화 상대 수 |
| 호감도 분포 | 호감도 구간별 쌍 분포, 임계치 도달 쌍 수 |
| 비용 모니터링 | 일일 AI API 비용, 유저당 비용 (상한 초과 경고) |
| 매출 (라운드 4~) | 매칭 오픈권 결제 수·전환율, 카톡 분석 크로스셀 |

**깊은 분석이 필요할 때의 동선**: 인사이트 탭에서 이상 신호 발견 → PostHog(왜 이탈하는지 리코딩 확인) / GA4(어느 채널 문제인지) 로 이동. 인사이트 탭에 각 도구 바로가기 링크를 둔다.

## 각 라운드 시작 전 결정할 것

| 라운드 | 결정 사항 |
|--------|----------|
| 1 | 검사 주제 확정, 초기 유입 채널 1곳 |
| 2 | 오픈 방식 (사전신청자 동시 오픈 여부), 봇 모델/비용 상한 |
| 3 | 시드 봇 허용 여부, 임계치 초기값(75% 제안), 일일 API 비용 상한 |
| 4 | 첫 매칭 무료 정책, 가격, 성인 인증 수단 |
