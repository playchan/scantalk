# 제품 요구사항 정의서 (PRD)

> 이 문서는 1차 MVP에서 무엇을 만들고 무엇을 만들지 않을지를 정의합니다.
> 개발을 시작하기 전에 반드시 읽어야 하는 기준 문서입니다.

---

## 1. 서비스 목적

카카오톡 대화 캡처를 업로드하면 AI가 연애 상황을 분석해주는 유료 서비스.
1차 MVP의 핵심 목표는 **"유료 상품이 실제로 팔리는지 검증"**하는 것.

---

## 2. 주요 사용자

| 구분 | 설명 |
|------|------|
| 일반 사용자 | 썸·소개팅·연애·재회 상황에서 도움을 원하는 사람 |
| 관리자 | 분석 신청을 처리하고 리포트를 작성하는 운영자 |

---

## 3. 핵심 흐름

```
[사용자] 신청 → 결제 → [관리자] 확인 → AI 초안 생성 → 검수 → 공개 → [사용자] 결과 확인
```

---

## 4. 사용자 기능 상세

### 4-1. 랜딩페이지
- 서비스 소개 (한 줄 카피 + 서비스 흐름)
- 유료 상품 3종 소개
- 회원가입 / 로그인 버튼
- 모바일 최적화 필수

### 4-2. 회원가입 / 로그인
- 이메일 + 비밀번호 방식 (Supabase Auth)
- 이메일 인증 (선택 — 1차에서 간소화 가능)

### 4-3. 마이페이지
- 내 분석 신청 내역 목록 (날짜, 상품, 상태)
- 리포트 확인 링크 (공개된 것만)
- 매칭 신청 여부 표시

### 4-4. 연애 성향 테스트
- 10~15개 질문 (취향, 대화 스타일, 연애관, 성격)
- 결과 저장 (DB에 저장, 추후 매칭에 활용)
- 결과 화면 표시 (간단한 유형 설명)

### 4-5. 카카오톡 분석 신청
- 관계 상황 선택: 썸 / 소개팅 / 연애 / 재회
- 고민 내용 텍스트 입력 (최소 50자 이상 유도)
- 카톡 캡처 이미지 업로드 (최대 5장)
- 개인정보 가림 안내 문구 + 확인 체크박스 (필수)
- 체크박스 미선택 시 신청 버튼 비활성화

### 4-6. 상품 선택 + 결제 안내
- 3가지 상품 중 선택
- 선택한 상품 가격 + 결제 방법 안내
- 계좌번호 또는 외부 결제링크 제공
- "입금 확인 후 분석이 시작됩니다" 안내

### 4-7. 분석 결과 (리포트) 확인
- 관리자가 공개 처리한 리포트만 표시
- 리포트 내용: 상황 요약, 호감 가능성, 신호, 추천 답장, 코칭 등
- 미공개 상태면 "현재 분석 중입니다" 표시

### 4-8. 매칭 신청
- 매칭 희망 여부 선택 버튼
- 연애 성향 테스트 완료 여부 확인 (미완료 시 테스트 먼저 유도)
- 신청 완료 메시지 ("검토 후 연락드립니다")

---

## 5. 관리자 기능 상세

### 5-1. 관리자 로그인
- 일반 사용자와 별도 권한 (admin role)
- Supabase에서 특정 계정에 admin 권한 부여

### 5-2. 신청 목록
- 전체 신청 목록 (최신순)
- 필터: 결제 상태 / 처리 상태 / 상품 종류
- 각 항목: 신청일, 상품명, 결제 상태, 처리 상태

### 5-3. 신청 상세
- 신청자 정보 (이메일)
- 관계 상황, 고민 내용
- 업로드 이미지 (private URL로 안전하게 표시)
- 결제 상태 변경 (드롭다운)
- 처리 상태 변경 (드롭다운)
- AI 초안 생성 버튼
- 운영자 수정 텍스트 에디터
- 리포트 공개 버튼

### 5-4. AI 초안 생성
- 버튼 클릭 → 서버 사이드 API 호출 → Claude API 요청
- 고민 내용 + 관계 상황을 프롬프트에 포함
- 생성된 초안을 에디터에 자동 삽입

### 5-5. 매칭 신청자 목록
- 매칭 신청한 사용자 목록
- 연애 성향 테스트 결과 확인
